## 2. Clean Architecture & SOLID

### 2.1 Структура слоев
- [ ] Transport layer (handlers) - только HTTP логика
- [ ] Service/UseCase layer - бизнес-логика отчетов
- [x] Repository layer (database) - доступ к данным
- [ ] Разделение ответственности между слоями

### 2.2 DRY (Don't Repeat Yourself)
- [ ] Дублирование парсинга времени в handlers (start_time/end_time)
- [x] Дублирование логики категоризации (вынесено в categories.go)
- [ ] Общая функция для обработки ошибок

### 2.3 SOLID Principles
- [ ] S - Single Responsibility: handlers.go слишком большой
- [x] O - Open/Closed: расширяемость категорий (process_catalog)
- [ ] L - Liskov Substitution: интерфейсы для репозиториев
- [ ] I - Interface Segregation: мелкие интерфейсы
- [ ] D - Dependency Inversion: инъекция зависимостей
